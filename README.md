# depviz

Инструмент визуализации графа зависимостей пакетов Alpine Linux (apk).
Готовые менеджеры пакетов и библиотеки для получения зависимостей не используются.

## Настройки (config.yaml)

| Параметр | Описание |
|---|---|
| `package_name` | Имя анализируемого пакета |
| `repository` | URL репозитория (APKINDEX.tar.gz) или путь к тестовому файлу |
| `test_mode` | `true` — работа с тестовым файлом, `false` — с реальным репозиторием |
| `output_file` | Имя PNG-файла с изображением графа |
| `max_depth` | Максимальная глубина анализа зависимостей (не меньше 1) |

Путь к файлу конфигурации можно задать опцией `-config` (по умолчанию `config.yaml`).

## Функции

| Пакет | Функция | Назначение |
|---|---|---|
| `config` | `Load`, `Parse` | Чтение YAML-файла и проверка всех параметров |
| `apk` | `FetchIndex` | Скачивание `APKINDEX.tar.gz` по HTTP |
| `apk` | `ReadArchive` | Распаковка архива и поиск файла `APKINDEX` |
| `apk` | `ParseIndex` | Разбор записей пакетов (`P:`, `V:`, `D:`, `p:`) |
| `apk` | `DirectDeps` | Список прямых зависимостей пакета |
| `testrepo` | `Load` | Чтение тестового репозитория из текстового файла |
| `graph` | `Build` | Построение графа зависимостей рекурсивным DFS с учётом `max_depth` |
| `graph` | `Reverse` | Обращение рёбер графа: источник «кто зависит от пакета» |
| `graph` | `Reached` | Список всех пакетов, достигнутых при обходе (кроме корня) |
| `graph` | `Print` | Вывод рёбер графа, найденных циклов и отсутствующих пакетов |
| `viz` | `PlantUML` | Текстовое описание графа на языке PlantUML |
| `viz` | `Save` | Сохранение описания (`.puml`) и изображения графа (`.png`) |

## Как работает сбор данных

Программа скачивает `APKINDEX.tar.gz` по адресу из `repository`, распаковывает его
средствами стандартной библиотеки Go (`compress/gzip`, `archive/tar`) и разбирает файл `APKINDEX`.
Из записи пакета берутся поля `P:` (имя), `D:` (зависимости) и `p:` (что пакет предоставляет).
Зависимости вида `so:libc.musl-x86_64.so.1` сопоставляются с пакетом, который их предоставляет;
ограничения версий (`>=`, `=`, `<`, `~`) отбрасываются, конфликты (`!pkg`) пропускаются.

## Построение графа

Граф строится рекурсивным обходом в глубину (DFS). Корневой пакет имеет глубину 0,
зависимости пакета раскрываются, только пока его глубина меньше `max_depth`.
Если пакет уже встречался, но теперь найден по более короткому пути, он раскрывается заново,
чтобы ограничение глубины считалось по кратчайшему пути.

Циклы обнаруживаются по пакетам, которые сейчас находятся в стеке рекурсии:
ребро в такой пакет запоминается как цикл, и обход по нему не продолжается,
поэтому программа не зацикливается.

## Визуализация

После построения граф переводится в описание на языке PlantUML: каждый пакет — компонент `[имя]`,
каждая зависимость — стрелка `-->`. Корневой пакет выделен голубым цветом, рёбра, замыкающие цикл,
показаны красными стрелками `-[#red]->`. Описание выводится на экран и сохраняется в файл
с именем `output_file` и расширением `.puml`, а изображение — в PNG-файл `output_file`.
PNG создаётся вызовом `plantuml -tpng -pipe`, поэтому PlantUML должен быть установлен:

```bash
brew install plantuml        # macOS
sudo apt install plantuml    # Ubuntu
```

Пример для тестового графа `complex.txt`:

```
@startuml
[A] #LightBlue
[A] --> [B]
[A] --> [C]
[B] --> [D]
[B] --> [E]
[D] -[#red]-> [B]
[E] --> [G]
[G] -[#red]-> [A]
[G] --> [X]
[C] --> [E]
[C] --> [F]
[F] -[#red]-> [F]
@enduml
```

### Примеры для трёх пакетов

В папке `examples/` лежат конфигурации для пакетов `busybox`, `curl`, `git` из репозитория
Alpine v3.20 и для тестового графа `complex.txt`. Команда

```bash
make examples
```

строит для каждого из них описание `examples/<пакет>.puml` и изображение `examples/<пакет>.png`.
Описания `.puml` хранятся в репозитории, изображения PNG как бинарные файлы в репозиторий не добавляются
и создаются заново этой командой.

### Сравнение со штатными инструментами Alpine

Штатный инструмент визуализации — `apk dot`, он выводит граф зависимостей на языке Graphviz.
Его можно запустить в контейнере Alpine той же версии:

```bash
docker run --rm alpine:3.20 sh -c "apk update -q && apk dot curl" > curl.dot
docker run --rm alpine:3.20 sh -c "apk update -q && apk info -R curl"
```

#### Результат сравнения для `curl` (Alpine 3.20)

`apk info -R curl` выводит зависимости в том виде, как они записаны в индексе:

```
curl-8.14.1-r2 depends on:
libcurl=8.14.1-r2
so:libc.musl-aarch64.so.1
so:libcurl.so.4
so:libz.so.1
```

depviz для того же пакета:

```
curl -> [libcurl musl zlib]
libcurl -> [ca-certificates brotli-libs musl c-ares libcrypto3 libidn2 nghttp2-libs libpsl libssl3 zlib zstd-libs]
ca-certificates -> [yash-binsh musl libcrypto3]
...
```

**Что совпало.** Прямые зависимости `curl` совпадают: `so:libc.musl…` предоставляет `musl`,
`so:libz.so.1` — `zlib`, а `libcurl=8.14.1-r2` и `so:libcurl.so.4` указывают на один пакет `libcurl`.
Все 11 зависимостей `libcurl` и зависимости `libssl3`, `libpsl`, `libidn2` и других библиотек
совпадают с рёбрами графа `apk dot`.

**Расхождения и их причины.**

1. **Несколько поставщиков одной зависимости.** `ca-certificates` зависит от `/bin/sh`, который
   предоставляют `busybox-binsh`, `dash-binsh` и `yash-binsh`. `apk dot` рисует рёбра ко всем
   поставщикам, а depviz выбирает одного, последнего найденного в индексе (`yash-binsh`).
   При установке apk выбрал бы поставщика с наибольшим приоритетом (`busybox-binsh`).
2. **Глубина.** `apk dot` строит полный граф и поэтому показывает ещё `busybox`, `dash`, `yash`,
   `libncursesw` и `ncurses-terminfo-base`. depviz с `max_depth: 3` не раскрывает пакеты
   на третьем уровне (`yash-binsh`, `libunistring`).
3. **Циклы.** Красные рёбра `apk dot` — это циклы вида `dash -> dash-binsh -> dash`. В графе depviz
   их нет, потому что пакеты `dash` и `yash` не попали в него (см. пункты 1 и 2).
4. **Повторные рёбра.** `apk dot` выводит ребро для каждой записи зависимости, поэтому
   `curl -> libcurl` и `libssl3 -> libcrypto3` встречаются дважды (по имени и по `so:`).
   depviz объединяет их в одно ребро.
5. **Подписи и архитектура.** `apk dot` подписывает вершины версией (`curl-8.14.1-r2`), а рёбра —
   исходной записью (`so:libz.so.1`). depviz показывает только имена пакетов. Docker на Mac с процессором
   Apple запускает Alpine для `aarch64`, поэтому в выводе apk встречается `so:libc.musl-aarch64.so.1`,
   а depviz читает индекс `x86_64`. Набор пакетов при этом одинаковый.
6. **Версии и конфликты.** depviz отбрасывает ограничения версий (`=8.14.1-r2`) и записи-конфликты `!пакет`.

## Обратные зависимости

Опция `-reverse` выводит пакеты, которые зависят от `package_name` (напрямую или транзитивно).
Функция `graph.Reverse` один раз проходит по всем пакетам репозитория и обращает рёбра,
после чего к результату применяется тот же рекурсивный DFS (`graph.Build`)
с тем же учётом `max_depth` и циклов.

```
$ go run ./src -config config.test.yaml -reverse
Обратные зависимости пакета A:
  A <- [C]
  C <- [B]
  B <- [A]
Обнаружен цикл: B <- A
От пакета A зависят: C, B
```

## Тестовый режим

При `test_mode: true` параметр `repository` — путь к текстовому файлу,
где пакеты названы большими латинскими буквами:

```
# комментарий
A: B C
B: D
C: D
D:
```

Готовые примеры лежат в `tests/testdata/`:

| Файл | Что демонстрирует |
|---|---|
| `simple.txt` | Ромб: общая зависимость D у B и C |
| `cycle.txt` | Цикл A → B → C → A |
| `deep.txt` | Цепочка A → B → C → D → E для проверки `max_depth` |
| `shortcut.txt` | Пакет, достижимый длинным и коротким путём |
| `complex.txt` | Несколько циклов, самозависимость F → F и отсутствующий пакет X |

Запуск на тестовом репозитории:

```bash
go run ./src -config config.test.yaml           # граф зависимостей
go run ./src -config config.test.yaml -reverse  # обратные зависимости
```

## Сборка и запуск

```bash
make build   # сборка в bin/depviz
make run     # запуск с config.yaml
make test    # запуск тестов
make examples  # построение графов для примеров из examples/
```

```
$ go run ./src -config config.test.yaml
Граф зависимостей пакета A:
  A -> [B]
  B -> [C]
  C -> [A]
Обнаружен цикл: C -> A
```
