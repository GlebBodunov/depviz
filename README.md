# depviz

Инструмент визуализации графа зависимостей пакетов Alpine Linux (apk).
Готовые менеджеры пакетов и библиотеки для получения зависимостей не используются.

## Настройки (config.yaml)

| Параметр | Описание |
|---|---|
| `package_name` | Имя анализируемого пакета |
| `repository` | URL репозитория (APKINDEX.tar.gz) или путь к тестовому файлу |
| `test_mode` | `true` — работа с тестовым файлом, `false` — с реальным репозиторием |
| `output_file` | Имя PNG-файла с изображением графа |
| `max_depth` | Максимальная глубина анализа зависимостей (не меньше 1) |

Путь к файлу конфигурации можно задать опцией `-config` (по умолчанию `config.yaml`).

## Функции

| Пакет | Функция | Назначение |
|---|---|---|
| `config` | `Load`, `Parse` | Чтение YAML-файла и проверка всех параметров |
| `apk` | `FetchIndex` | Скачивание `APKINDEX.tar.gz` по HTTP |
| `apk` | `ReadArchive` | Распаковка архива и поиск файла `APKINDEX` |
| `apk` | `ParseIndex` | Разбор записей пакетов (`P:`, `V:`, `D:`, `p:`) |
| `apk` | `DirectDeps` | Список прямых зависимостей пакета |
| `testrepo` | `Load` | Чтение тестового репозитория из текстового файла |
| `graph` | `Build` | Построение графа зависимостей рекурсивным DFS с учётом `max_depth` |
| `graph` | `Print` | Вывод рёбер графа, найденных циклов и отсутствующих пакетов |

## Как работает сбор данных

Программа скачивает `APKINDEX.tar.gz` по адресу из `repository`, распаковывает его
средствами стандартной библиотеки Go (`compress/gzip`, `archive/tar`) и разбирает файл `APKINDEX`.
Из записи пакета берутся поля `P:` (имя), `D:` (зависимости) и `p:` (что пакет предоставляет).
Зависимости вида `so:libc.musl-x86_64.so.1` сопоставляются с пакетом, который их предоставляет;
ограничения версий (`>=`, `=`, `<`, `~`) отбрасываются, конфликты (`!pkg`) пропускаются.

## Построение графа

Граф строится рекурсивным обходом в глубину (DFS). Корневой пакет имеет глубину 0,
зависимости пакета раскрываются, только пока его глубина меньше `max_depth`.
Если пакет уже встречался, но теперь найден по более короткому пути, он раскрывается заново,
чтобы ограничение глубины считалось по кратчайшему пути.

Циклы обнаруживаются по пакетам, которые сейчас находятся в стеке рекурсии:
ребро в такой пакет запоминается как цикл, и обход по нему не продолжается,
поэтому программа не зацикливается.

## Тестовый режим

При `test_mode: true` параметр `repository` — путь к текстовому файлу,
где пакеты названы большими латинскими буквами:

```
# комментарий
A: B C
B: D
C: D
D:
```

Готовые примеры лежат в `tests/testdata/`:

| Файл | Что демонстрирует |
|---|---|
| `simple.txt` | Ромб: общая зависимость D у B и C |
| `cycle.txt` | Цикл A → B → C → A |
| `deep.txt` | Цепочка A → B → C → D → E для проверки `max_depth` |
| `shortcut.txt` | Пакет, достижимый длинным и коротким путём |
| `complex.txt` | Несколько циклов, самозависимость F → F и отсутствующий пакет X |

Запуск на тестовом репозитории:

```bash
go run ./src -config config.test.yaml
```

## Сборка и запуск

```bash
make build   # сборка в bin/depviz
make run     # запуск с config.yaml
make test    # запуск тестов
```

## Пример

```
$ go run ./src -config config.test.yaml
Граф зависимостей пакета A:
  A -> [B]
  B -> [C]
  C -> [A]
Обнаружен цикл: C -> A
```
